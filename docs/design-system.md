## 0. 一句话

**作品集本身是一张“会注释的工作画布”：真实的作品放在白色画框里，我的声音以注释的形式出现在旁边。**

作品集的外壳（画布、画框、标签、注释）属于我；画框里面的产品界面属于产品本身——**永远不用作品集的颜色和字体去“重画”产品界面**。上一版的问题正是在这里：演示区把 PlayBook、SMT、共享冰箱都重画成了同一套蓝白控件，看起来像是真实界面，其实不是。

## 1. 设计原则

| # | 原则 | 在页面上意味着 |
|---|---|---|
| 1 | **真实作品优先** | 每张图都来自原稿、原型或实拍；首页卡片不再用抽象示意图代替作品。 |
| 2 | **注释，而不是装饰** | 所有编号、标签、虚线都必须对应真实信息（步骤顺序、界面位置、来源）。没有意义的装饰编号不用。 |
| 3 | **说清楚什么是真的** | 每个图框右上角都有来源标签：原始界面 / 原始线框 / 团队 UI / 研究材料 / 实拍 / 原始录屏 / 可运行原型 / 按原稿复刻。 |
| 4 | **默认易读** | 字体为易读性而生；正文对比度 ≥ 4.5:1；尊重“减少动态效果”设置；中英双语各自排版。 |

### 3.2 字体与字号

- 西文正文/标题：`Atkinson Hyperlegible Next`（200–800 可变，自托管 woff2，约 90KB）
- 注释/标签/数字：`Atkinson Hyperlegible Mono`
- 中文：`PingFang SC` → `Hiragino Sans GB` → `Noto Sans SC` → `Microsoft YaHei`（系统字体，不加载大体积中文字库）

| 角色 | 桌面 | 手机 | 字重 | 字距 |

| H1（案例标题） | 56 / 1.12 | 36 | 800 | -0.015em（中文 700 / 0） |
| H2（章节） | 36 | 28 | 800 | -0.015em |
| H3 | 22 | 22 | 800 | — |
| Lead 导语 | 21 / 1.6 | 18 | 400 | — |
| Body 正文 | 18 / 1.65（中文 1.8） | 18 | 400 | — |
| Small | 15 | 15 | 400 | — |
| Label（Mono，大写） | 13 | 13 | 500 | +0.04em（中文不大写，+0.06em） |
| Micro（Mono） | 12 | 12 | 400 | — |

### 3.3 间距、圆角、阴影、动效

- 间距：4 的倍数 `4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96 · 128`
- 栅格：12 列，最大 1200px，列间距 24（手机 16），页边距 48 / 32 / 20
- 圆角：画框 6 · 卡片 10 · 胶囊 999 · 手机外壳 34（画框是“文件”，所以比常见卡片更利落）
- 阴影：`--shadow-frame` 一层 1px 描边 + 一层柔和投影；悬停时 `--shadow-lift`
- 动效：`160ms`（微交互）· `280ms`（状态切换）· `600ms`（进入视野）；曲线 `cubic-bezier(.2,.7,.2,1)`；开启“减少动态效果”时全部取消

## 4. 组件

| 组件 | 作用 | 规则 |
|---|---|---|
| **Top bar** | 品牌 + 导航 + 语言切换 | 滚动后出现 1px 底线；手机端收进“菜单”；语言切换始终可见 |
| **Frame 画框** | 承载一切作品图 | 上方必有 **Frame label**：项目色块 + 名称（Mono）+ 右侧 **来源标签** |
| **来源标签 Provenance tag** | 说明这是什么 | 原始界面 / 原始线框 / 研究材料 / 实拍 / 原始录屏（中性）· 团队 UI（米色）· 可运行原型（青色）· 按原稿复刻（珊瑚色） |
| **Pin 注释编号** | 指向图上的具体位置 | 青色圆点 + 白色 Mono 数字；编号必须与旁边的说明一一对应 |
| **Tobie’s note 注释卡** | 我的判断和取舍 | 头像 + “Tobie 的注释” + 一句话；替代旧版的大字引用框 |
| **Method strip** | 首页“我怎么工作” | 五步与自画像上的五个物件联动。2026-11-15 起自画像不再放数字编号，也不放画框标签：平时每个物件上只有一个很小的呼吸点；悬停、聚焦或点到物件（或下面对应的步骤），其余部分压暗，物件旁贴出一张说明。步骤条里的圆点是从自画像上截下来的小物件。手机上点一下固定，再点或点别处取消 |
| **Work item** | 首页项目 | 左右交替：8 列真实界面拼贴 + 4 列文字；标题用“结论句” |
| **Spec table** | 案例基本信息 | 背景 / 职责 / 时间 / 交付，Mono 小标签 |
| **Contents** | 案例目录 | 桌面端吸顶，当前章节高亮；手机端变为横向胶囊 |
| **Figure** | 证据图 | 单图 / 手机条（长截图裁成一屏高，点击放大看全图）/ 左右对照 / 角色表情 |
| **Prototype player** | 原稿界面上的可点击原型 | 见第 5 节 |
| **Guided tour** | 在一张原始界面上分步导览 | 只平移、缩放、加框，不改界面 |
| **Component replica** | 用代码复刻的原稿组件 | 颜色、行高、数值全部取自原稿；标签必须写“按原稿复刻” |
| **Live embed** | 嵌入真正可运行的原型 | 点击后才加载；提供入口跳转与“新窗口打开” |
| **Contact** | 联系 | 深墨色区块；邮箱、LinkedIn、PDF；企鹅作为签名 |
| **Structure mode** | 页脚开关 | 用虚线框显示页面由哪些组件组成——作品集自己的“设计规范”随手可见 |

## 5. 演示真实性规范（这次修改的核心）

### 5.1 规则

1. **只用原稿里存在的界面和状态。** 不新增按钮、不新增步骤、不编造数值。
2. **热点只放在真实控件上。** 原稿中不可用的按钮，在演示里也不可用。
3. **原稿没有下一屏时，演示就在这里结束，并直说。**（例：PlayBook 合成在“Sure”之后结束。）
4. **我的注释与产品界面在视觉上分开**：注释永远在界面外侧的注释卡里。
5. **每个演示底部都有来源说明**：界面来自哪个文件、我负责哪部分、做了哪些处理。
6. **需要代码复刻时（组件级），逐项取值并标注“按原稿复刻”**，数值与原稿截图一致。
7. **有可运行原型时，直接嵌入真正的原型**，不再另做示意版。
8. **直接操作（拖动、框选）只通向原稿或录屏里已有的画面。** 放下、松手以后落到的那一屏，必须是原稿或录屏里本来就有的状态。例外只有按规则 6 复刻的部件，而且要在来源说明里写明（例：PlayBook 评论演示里访客自己拖框时出现的选框、回复框和圆点）。（2026-11-15 加）

### 5.3 图片处理边界

- 允许：缩放、WebP 压缩、裁切到一屏高度（点击放大看全图）、青桔原型板去掉连线箭头。
- 不允许：改界面文字、改颜色、合成原稿中不存在的状态。

## 6. 双语排版

- 中文标题不用负字距，字重 700，行高 1.3；正文行高 1.8。
- 中文 Display 最大 58px，并手动断行，避免“懂。”这类孤字。
- Mono 标签在中文下不大写、略加字距；中文会回退到苹方，不强行用等宽。
- 原稿界面语言保持原样（青桔、SMT 为中文），英文版在图注中说明。
- 每一页的语言切换都指向“同一页的另一种语言”。

## 7. 无障碍

- 焦点：2px 墨色描边 + 珊瑚色光晕；所有热点都是带名称的 `<button>`。
- 原型：步骤条可键盘操作；注释区 `aria-live="polite"`；嵌入原型点击后才加载。
- 图片都有替代文字；长截图可放大；表格可横向滚动并有区域名称。
- 手机 390px 无横向溢出（已用 Playwright 检查全部 10 页）。

## 8. 维护

- 新增图片：放入源文件路径 → 在 `tools/prepare_assets.py` 登记 → `python3 tools/prepare_assets.py`。
- 新增证据图：在 `figures.py` 对应章节添加，写清 `prov` 与中英文图注。
- 新增演示：在 `prototypes.py` 用 `FLOWS`（点击原型）或导览/复刻模板；坐标用原图像素，不写死百分比。
- 生成：`python3 build.py`；检查：`python3 verify.py` 与 `node --test tests/`。
