## 0. 一句话

**作品集本身是一张“会注释的工作画布”：真实的作品放在白色画框里，我的声音以注释的形式出现在旁边。**

作品集的外壳（画布、画框、标签、注释）属于我；画框里面的产品界面属于产品本身——**永远不用作品集的颜色和字体去“重画”产品界面**。上一版的问题正是在这里：演示区把 PlayBook、SMT、共享冰箱都重画成了同一套蓝白控件，看起来像是真实界面，其实不是。

## 1. 设计原则

| # | 原则 | 在页面上意味着 |
|---|---|---|
| 1 | **真实作品优先** | 每张图都来自原稿、原型或实拍；首页卡片不再用抽象示意图代替作品。 |
| 2 | **注释，而不是装饰** | 所有编号、标签、虚线都必须对应真实信息（步骤顺序、界面位置、来源）。没有意义的装饰编号不用。 |
| 3 | **说清楚什么是真的** | 每个图框右上角都有来源标签：原始界面 / 原始线框 / 团队 UI / 研究材料 / 实拍 / 原始录屏 / 可运行原型 / 按原稿复刻 / 2026 年用代码重做 · 界面取自原稿。 |
| 4 | **默认易读** | 字体为易读性而生；正文对比度 ≥ 4.5:1；尊重“减少动态效果”设置；中英双语各自排版。 |

- 中文：`PingFang SC` → `Hiragino Sans GB` → `Noto Sans SC` → `Microsoft YaHei`（系统字体，不加载大体积中文字库）

### 3.3 间距、圆角、阴影、动效

- 间距：4 的倍数 `4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96 · 128`
- 栅格：12 列，最大 1200px，列间距 24（手机 16），页边距 48 / 32 / 20
- 圆角：画框 6 · 卡片 10 · 胶囊 999 · 手机外壳 34（画框是“文件”，所以比常见卡片更利落）
- 阴影：`--shadow-frame` 一层 1px 描边 + 一层柔和投影；悬停时 `--shadow-lift`
- 动效：`160ms`（微交互）· `280ms`（状态切换）· `600ms`（进入视野）；曲线 `cubic-bezier(.2,.7,.2,1)`；开启“减少动态效果”时全部取消

## 4. 组件

| 组件 | 作用 | 规则 |
|---|---|---|
| **Top bar** | 品牌 + 导航 + 语言切换 | 滚动后出现 1px 底线；手机端收进“菜单”；语言切换始终可见 |
| **Case brief 案例摘要** | 案例标题下面的三行：问题 / 我的关键决定 / 结果 | 细线表格，和下面的 Spec table 连成一张表；左列是 Mono 小标签，右列正文。数据在 `cases.py` 的 `brief`。只写结论，不写声明句（2026-11-16） |
| **Decision 决策块** | 章节里的一个关键决策，四行：问题 / 考虑过的方案 / 为什么没选 / 结果 | 沿用 Case brief 的细线表格（`case-brief case-decision`），不另做样式；放在正文之后、注释卡和图之前。数据在 `cases.py` 该节的可选键 `decision`（四行，每行 `[zh, en]`），行名在 `build.py` 的 `DECISION_LABELS`。依据不上页面，记在 `docs/sources.md`（2026-11-16，目前只有 PlayBook 04、06、07 三节用） |
| **Rows 细线表** | 章节里几行并列的事（目前只有 Agent Matrix 06 节的四个缺口） | 沿用 Case brief 的细线表格（`case-brief case-decision`），不另做样式；插在正文指定的一段后面。左边一格是 Mono 小标签，右边一句加粗、下面一句说明。数据在 `cases.py` 该节的可选键 `rows`（`after` 是插在第几段后面，`items` 每行三项，都 `[zh, en]`）（2026-11-17） |
| **Frame 画框** | 承载一切作品图 | 上方必有 **Frame label**：项目色块 + 名称（Mono）+ 右侧 **来源标签**。变体：**平铺（flat）**——图本身就是页面底色（`#ECF0ED`）的图表用，图框不要白底、描边和投影，图直接落在页面上；`figures.py` 的 image 条目写 `'bg': '#ECF0ED', 'flat': True`，`build.py` 把它写成该图框的内联样式，`styles.css` 不动。Frame label、图注、放大按钮照常。2026-11-16 起只有青桔 07 节两张图用 |

## 5. 演示真实性规范（这次修改的核心）

### 5.1 规则

1. **只用原稿里存在的界面和状态。** 不新增按钮、不新增步骤、不编造数值。
2. **热点只放在真实控件上。** 原稿中不可用的按钮，在演示里也不可用。
3. **原稿没有下一屏时，演示就在这里结束，并直说。**（例：PlayBook 合成在“Sure”之后结束。）
4. **我的注释与产品界面在视觉上分开**：注释永远在界面外侧的注释卡里。
5. **每个演示底部一句来源说明**：界面来自哪里、我负责哪部分。做了哪些处理记在 `docs/sources.md`，不写在页面上。（2026-11-16 本人定，卡 20261116-007：页面不写防御句。）
6. **需要代码复刻时（组件级），逐项取值并标注“按原稿复刻”**，数值与原稿截图一致。
7. **有可运行原型时，直接嵌入真正的原型**，不再另做示意版。
8. **用代码重做的 PlayBook Studio 演示可以自由操作，但要守下面四条。**（2026-11-16，本人在审核卡 20261115-057 上的决定。它替换了 2026-11-15 的旧规则「直接操作只通向原稿或录屏里已有的画面」：旧做法把录屏拆成一帧一帧，访客只能照固定顺序点。本人的意见是体验太差、还不如直接放视频；不用照定死的交互走，东西可以来回动，设一个边界就好；既然用代码做，就不必只出现录屏里有过的画面。）
   - **标明是重做的。** 画框标签写「2026 年用代码重做 · 界面取自原稿」；底部来源说明只一句：「2026 年按原稿和当年录屏用代码重做，界面元素取自原稿。」哪些是录屏画面本身、哪些是重画的、哪些规矩是重做时定的，记在 `docs/sources.md`（已有），不写在页面上。（2026-11-16 本人定，卡 20261116-007。改之前这句固定带「不是当年的交付物」，后面还要逐项写清。）
   - **界面取自原稿。** 不动的部分直接用录屏画面；图标从画面里裁；重画的部件（栏、物品卡片、And / Or、概率条、连线、选框、圆点、气泡）按画面量出的尺寸和颜色画，不重新设计。作品集自己的东西（画面下方的按钮、提示、「读作」那一行）放在画面外面，用作品集的样式，不混进产品界面。
   - **不编造原稿没有的数据。** 配方只用物品库里现有的八样物品；原稿只给纸鹤和红耳机画了详情，别的物品点了就直说没有；录屏里看不清的东西（红耳机关系网底部露出的半件物品）不画。
   - **边界写在数据里，有测试守着。** 每栏能放几样、一组几样、最多几个标记，写在 `prototypes.py` 的 `STUDIO[...]['limits']`；不合法的落点一律弹回原处并说明原因。`tests/recipe_rules.test.js` 用上线的同一份规则检查上限、非法落点和一万次随机操作；`tests/test_prototypes.py` 检查放满时不溢出、来源说明里写明是重做的。
   这条只管这三个演示。其余演示仍按规则 1–7；原始录屏继续放在这三个演示下面。

### 5.3 图片处理边界

- 允许：缩放、WebP 压缩、裁切到一屏高度（点击放大看全图）、青桔原型板去掉连线箭头。

## 6. 双语排版

- 中文标题不用负字距，字重 700，行高 1.3；正文行高 1.8。
- 中文 Display 最大 58px，并手动断行，避免“懂。”这类孤字。
- Mono 标签在中文下不大写、略加字距；中文会回退到苹方，不强行用等宽。
- 原稿界面语言保持原样（青桔、SMT 为中文），英文版在图注中说明。
- 每一页的语言切换都指向“同一页的另一种语言”。

## 7. 无障碍

- 焦点：2px 墨色描边 + 珊瑚色光晕；所有热点都是带名称的 `<button>`。
- 原型：步骤条可键盘操作；注释区 `aria-live="polite"`；嵌入原型点击后才加载。
- 重做的三个演示：凡是拖动能做的事，画面下方都有按钮能做（先点物品再点目的地、往前 / 往后、拿掉）；状态提示是 `role="status"`；回车拿起、Delete 拿掉、Esc 放下或退出放大。
- 图片都有替代文字；长截图可放大；表格可横向滚动并有区域名称。
- 手机 390px 无横向溢出（已用 Playwright 检查全部 10 页）。

## 8. 维护

- 新增图片：放入源文件路径 → 在 `tools/prepare_assets.py` 登记 → `python3 tools/prepare_assets.py`。
- 新增证据图：在 `figures.py` 对应章节添加，写清 `prov` 与中英文图注。
- 新增演示：在 `prototypes.py` 用 `FLOWS`（点击原型）或导览/复刻模板；坐标用原图像素，不写死百分比。
- 新增或修改重做的演示：数据和上限在 `prototypes.py` 的 `STUDIO`，引擎在 `dist/prototype.js` 第 6 节，样式在 `dist/styles.css` 末尾；需要新的小部件时在 `tools/extract_playbook_parts.py` 里从录屏画面裁，再用 `tools/prepare_assets.py <名字>` 单独导出。
- 生成：`python3 build.py`；检查：`python3 -m unittest discover tests`（会顺带跑 `node tests/recipe_rules.test.js`）与 `python3 verify.py`。
