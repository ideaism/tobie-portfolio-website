## 0. 一句话

**作品集本身是一张“会注释的工作画布”：真实的作品放在白色画框里，我的声音以注释的形式出现在旁边。**

作品集的外壳（画布、画框、标签、注释）属于我；画框里面的产品界面属于产品本身——**永远不用作品集的颜色和字体去“重画”产品界面**。上一版的问题正是在这里：演示区把 PlayBook、SMT、共享冰箱都重画成了同一套蓝白控件，看起来像是真实界面，其实不是。

## 1. 设计原则

| # | 原则 | 在页面上意味着 |
|---|---|---|
| 1 | **真实作品优先** | 每张图都来自原稿、原型或实拍；首页卡片不再用抽象示意图代替作品。 |
| 2 | **注释，而不是装饰** | 所有编号、标签、虚线都必须对应真实信息（步骤顺序、界面位置、来源）。没有意义的装饰编号不用。 |
| 3 | **说清楚什么是真的** | 每个图框右上角都有来源标签：原始界面 / 原始线框 / 团队 UI / 研究材料 / 实拍 / 原始录屏 / 可运行原型 / 按原稿复刻 / 按原稿还原 · 界面取自原稿（2026-11-25 起不写年份，见第 5 节规则 11）。 |
| 4 | **默认易读** | 字体为易读性而生；正文对比度 ≥ 4.5:1；尊重“减少动态效果”设置；中英双语各自排版。 |
| 5 | **展开和滑动要像真产品** | 2026-11-25 本人打回卡 20261126-005 后定。所有点开的内容（折叠、Tab、展开区）点开后标题吸在顶栏下面，收起时页面停回这一行；页面里自己能滑的东西（滑动窗、嵌入的原型、侧栏）滑到头不带着整页走；左右两栏一高一矮时，矮的那栏吸顶跟着走，比一屏高就在栏里自己滑，滑到底也不被推到别的东西下面；截图里的界面，原产品里不跟着滑的部分（顶部条、侧栏、底部操作栏、吸顶侧栏）在滑动窗里也不跟着滑。验收要用无头 Chrome 在 1440 和 390 真滚、真点，看数字，不能只截静态图。 |

| Token | 值 | 用途 | 对比度 |
|---|---|---|---|
| `--canvas` | `#ECF0ED` | 页面背景 | — |

| `--structure` | `#7B61FF` | 仅“显示页面结构”模式 | — |

### 3.2 字体与字号

- 西文正文/标题：`Atkinson Hyperlegible Next`（200–800 可变，自托管 woff2，约 90KB）
- 注释/标签/数字：`Atkinson Hyperlegible Mono`
- 中文：`PingFang SC` → `Hiragino Sans GB` → `Noto Sans SC` → `Microsoft YaHei`（系统字体，不加载大体积中文字库）

| 角色 | 桌面 | 手机 | 字重 | 字距 |
|---|---|---|---|---|
| Display（首页主标题） | 76 / 1.02 | 44 | 800 | -0.022em（中文 0，最大 58px） |
| H1（案例标题） | 56 / 1.12 | 36 | 800 | -0.015em（中文 700 / 0） |
| H2（章节） | 36 | 28 | 800 | -0.015em |
| H3 | 22 | 22 | 800 | — |
| Lead 导语 | 21 / 1.6 | 18 | 400 | — |
| Body 正文 | 18 / 1.65（中文 1.8） | 18 | 400 | — |
| Small | 15 | 15 | 400 | — |
| Label（Mono，大写） | 13 | 13 | 500 | +0.04em（中文不大写，+0.06em） |
| Micro（Mono） | 12 | 12 | 400 | — |

### 3.3 间距、圆角、阴影、动效

- 间距：4 的倍数 `4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96 · 128`
- 栅格：12 列，最大 1200px，列间距 24（手机 16），页边距 48 / 32 / 20
- 圆角：画框 6 · 卡片 10 · 胶囊 999 · 手机外壳 34（画框是“文件”，所以比常见卡片更利落）
- 阴影：`--shadow-frame` 一层 1px 描边 + 一层柔和投影；悬停时 `--shadow-lift`
- 动效：`160ms`（微交互）· `280ms`（状态切换）· `600ms`（进入视野）；曲线 `cubic-bezier(.2,.7,.2,1)`；开启“减少动态效果”时全部取消

## 4. 组件

| 组件 | 作用 | 规则 |
|---|---|---|
| **Top bar** | 品牌 + 导航 + 语言切换 | 滚动后出现 1px 底线；手机端收进“菜单”；语言切换始终可见 |
| **Case brief 案例摘要** | 案例标题下面的三行：问题 / 我的关键决定 / 结果 | 细线表格，和下面的 Spec table 连成一张表；左列是 Mono 小标签，右列正文。数据在 `cases.py` 的 `brief`。只写结论，不写声明句（2026-11-16） |
| **Decision 决策块** | 章节里的一个关键决策，四行：问题 / 考虑过的方案 / 为什么没选 / 结果 | 沿用 Case brief 的细线表格（`case-brief case-decision`），不另做样式；放在正文之后、注释卡和图之前。数据在 `cases.py` 该节的可选键 `decision`（四行，每行 `[zh, en]`），行名在 `build.py` 的 `DECISION_LABELS`。依据不上页面，记在 `docs/sources.md`（2026-11-16，目前只有 PlayBook 05、07、08 三节用；2026-11-24 起草助手挪到 04，原 04、06、07 顺延） |
| **Rows 细线表** | 章节里几行并列的事（目前只有 Agent Matrix 06 节的四个缺口） | 沿用 Case brief 的细线表格（`case-brief case-decision`），不另做样式；插在正文指定的一段后面。左边一格是 Mono 小标签，右边一句加粗、下面一句说明。数据在 `cases.py` 该节的可选键 `rows`（`after` 是插在第几段后面，`items` 每行三项，都 `[zh, en]`）（2026-11-17） |
| **Frame 画框** | 承载一切作品图 | 上方必有 **Frame label**：项目色块 + 名称（Mono）+ 右侧 **来源标签**。变体：**平铺（flat）**——图本身就是页面底色（`#ECF0ED`）的图表用，图框不要白底、描边和投影，图直接落在页面上；`figures.py` 的 image 条目写 `'bg': '#ECF0ED', 'flat': True`，`build.py` 把它写成该图框的内联样式，`styles.css` 不动。Frame label、图注、放大按钮照常。2026-11-16 起只有青桔 07 节两张图用 |
| **来源标签 Provenance tag** | 说明这是什么 | 原始界面 / 原始线框 / 研究材料 / 实拍 / 原始录屏（中性）· 按项目记录绘制（中性，2026-11-17，Agent Matrix 的四张图：照项目自己的记录画的图，不是界面截图）· 团队 UI（米色）· 可运行原型（青色）· 按原稿复刻（珊瑚色）· 原始界面 + 生成插画 / 生成插画（中性，2026-11-18，只用在封面：画面里有 AI 生成的装饰图时必须换成这两个之一，有真界面用前者，只有文字和生成图标用后者） |
| **Pin 注释编号** | 指向图上的具体位置 | 青色圆点 + 白色 Mono 数字；编号必须与旁边的说明一一对应。**图上编号（2026-11-26，第 2 批）**：手机条的条目在 `figures.py` 写 `'pins': {图名: [(号, x%, y%), …]}` 和 `'notes': [[zh, en], …]`（第 n 条对应 n 号），`build.py` 的 `pin_layer()` 在图上叠一层编号、`pin_notes()` 在图框下面列说明；可点击原型的某一屏写在 `prototypes.py` 那一屏的 `'pins'`、`'pin_notes'`，只在那一屏显示。一张图最多 3 个，放在要指的东西旁边的空白处，不压字、不盖物品（小图上编号 20–22px 占得多，摆完在 1440 和 390 各截一张看）。鼠标移到或 Tab 到说明上，对应编号放大 1.25 倍并加一圈喙色描边（`site.js`）；`prefers-reduced-motion` 时只加描边、不放大。编号层 `aria-hidden`，读屏读说明 |
| **Tobie’s note 注释卡** | 我的判断和取舍 | 头像 + “Tobie 的注释” + 一句话；替代旧版的大字引用框 |
| **Method strip** | 首页“我怎么工作” | 五步与自画像上的五个物件联动。2026-11-15 起自画像不再放数字编号，也不放画框标签：平时每个物件上只有一个很小的呼吸点；悬停、聚焦或点到物件（或下面对应的步骤），其余部分压暗，物件旁贴出一张说明。步骤条里的圆点是从自画像上截下来的小物件。手机上点一下固定，再点或点别处取消 |
| **Work item** | 首页项目 | 左右交替：8 列真实界面拼贴 + 4 列文字；标题用“结论句” |
| **Cover 封面** | 首页 Work item 左边的图，案例页顶部同一张 | 2026-11-18 起五张封面各用一种摆法，不套一个模子（本人在卡 20261118-013 第 1 版上打回「都像 PlayBook」）。写在 `build.py` 的 `collage(slug, lang)`，样式在 `styles.css` 的「卡 20261118-013 第 3 版」一段。现在四种：① **舞台**（PlayBook）：深色底一叠斜放的真界面。② **项目卡**（兴业 SMT，`.collage--idcard`，卡 20261118-017 选 S1）：浅蓝渐变底、三个彩色小标签（年份 / 平台 / 做了什么）、大标题、一句副标题、左下头像加一行「我负责什么」、右边一个生成的 3D 图标；不放截图。英文标题长，加 `.cover-title--long` 字小一号、折两行。③ **插画铺底 + 真界面立着**（冰箱、青桔，`.collage--ill`）：生成插画 `.cover-bg` 铺满，真界面 `.cover-phone` 正着立（白边、最多转 4°，看得清），可加装饰 `.cover-deco`（抠过底的生成图）或贴纸 `.cover-sticker`（项目原图，白描边）；位置写在 `build.py` 的内联样式里。④ **平放一张已通过的图**（Agent Matrix，临时）。封面上的字（小标签、标题、副标题）`aria-hidden`，读屏读下面卡片里的同一段字。尺寸全用 `cqw`（封面宽度的百分之几），手机上等比缩小；**容器自己的 padding、gap 不能用 cqw**（会按视口算），只给里面的元素用。鼠标移上去界面或图标往上浮一点，`prefers-reduced-motion` 时不动 |
| **Spec table** | 案例基本信息 | 背景 / 职责 / 时间 / 交付，Mono 小标签 |
| **Case tabs 案例 tab** | 一个案例页里放两个项目（目前只有兴业 SMT：兴业 SMT / 大通证券，2026-11-18 卡 030） | 返回链接下面一排文字 tab，选中的一个墨色字加青色下划线；每个 tab 有自己的开头（标题、导语、三行摘要、事实卡）和章节，节号各自从 01 数。数据在 `cases.py` 的 `tabs`：第一个 tab 就是案例本身，后面的 tab 带自己的 `title / deck / brief / facts / sections`，`id` 同时是锚点（`#daton` 直接打开）和 `figures.py` 的键名（`('daton', 1)`）。页面只能有一个 h1，后面 tab 的标题用 h2、样式同 h1。没开 JS 时 tab 是跳转链接、几块从上往下排；`site.js` 加上 tablist / tab / tabpanel、aria-selected，左右方向键、Home / End 切换；地址里的锚点在哪个 tab 里就打开哪个。手机上两个 tab 平分一行，字自己折行 |
| **Contents** | 案例目录 | 桌面端吸顶，当前章节高亮；手机端变为横向胶囊 |
| **Figure** | 证据图 | 单图 / 手机条（长截图裁成一屏高，点击放大看全图）/ 左右对照 / 角色表情。单图里有文字、中英文各导一张时，`figures.py` 用 `src`（中文页）和 `src_en`（英文页）。手机条里不是整屏的局部图（弹窗、卡片）写在 `partials`，不套竖屏框，按原比例完整显示、不超过原图宽度；这样的手机条在窄屏（520 以下）改成上下排，不左右滑（2026-11-16）。和手机一样宽、但高度不是一屏的图（要整张看的长稿、不到一屏的半屏）写在 `whole`：不套竖屏框，按原比例整张显示，顶对齐，带放大按钮。`partials`、`whole` 的条目可带第三项（在这一排里的位置）；`cap` 给 2 倍图定显示宽度上限。**单图滑动窗口（scroll）**：比 16:9 高、一屏放不下的整页稿，`figures.py` 的 image 条目写 `'scroll': True`，图放进 16:9 的固定窗口（宽度和普通单图一样），按窗口宽度整张显示、不缩小、不裁左右，超出部分在窗口里上下滑动看；窗口左下角一个 `.chip` 样式的小提示「可上下滑动 / Scroll to see more」，下沿一条很淡的渐隐，滑到底以后两者隐去。滚轮、触屏、方向键都用浏览器自己的滚动，不自动滚、不加动画；滚到头页面不跟着滚（`overscroll-behavior: contain`，2026-11-25 本人打回卡 20261126-005：「滑动的时候整个页面会跟着滑动」；手机上要接着滑页面，手指从图外面开始）；窗口可 Tab 聚焦（`role="region"` + 名称）。放大按钮在窗口右下角，点开是整张图。滚动只靠 CSS（`styles.css` 的 `.shot-scroll`），`site.js` 只管提示的显隐；打印时退回整张显示。默认关，2026-11-17 起只有 PlayBook 10 节三张用（卡 20261117-017；2026-11-24 前是 09 节）。**固定界面（fixed，2026-11-17 第 3 版）**：整页稿里本来就不跟着滑的界面（顶部条、左侧菜单、右侧栏），在同一条目加 `'fixed': {'of': 原图宽, 'top': 顶部条高, 'left': 左侧栏宽, 'right': 右侧栏宽}`（按原图像素量，不用的边不写）；窗口里叠一层不滑的同一张图，用 `clip-path` 只露出这几块，内容从它们下面滑过，最顶上时和原图第一屏一模一样。数字只写在 `figures.py`，`build.py` 换算成百分比，样式里不写死。开了 `fixed` 的窗口藏掉滚动条（不然滑的那层比固定层窄 15 像素，对不齐），提示和下沿渐隐只放在滑动的内容区上。**底部条和吸顶侧栏（2026-11-25，卡 20261126-005）**：原产品底部固定的操作栏写 `'bottom': 高, 'fade': 渐变高`（原图里那条栏连同上沿渐变的高度），窗口底边叠一层不滑的同一张图；原产品里先跟着滑、到顶后停住的侧栏写 `'sticky': [{'x': [左, 右], 'y': [上, 下], 'at': 停住的位置}]`，`site.js` 把窗口滑了多少交给 CSS（`--st`），这一栏先跟着上去、到 `at` 停住。目前只有 Agent Matrix 那张审核卡用（顶部那行导航、左菜单、底部决定栏不动，右栏背景 / 你定了以后 / 记录跟着上去再停在导航下面，和审核中心电脑版一样） |
| **Prototype player** | 原稿界面上的可点击原型 | 见第 5 节 |
| **Guided tour** | 在一张原始界面上分步导览 | 只平移、缩放、加框，不改界面 |

### 5.3 图片处理边界

- 允许：缩放、WebP 压缩、裁切到一屏高度（点击放大看全图）、青桔原型板去掉连线箭头。
- 不允许：改界面文字、改颜色、合成原稿中不存在的状态。
- **生成图（2026-11-18，卡 20261118-013 本人同意用生图找灵感、-017 通过）**：只能当封面装饰（底图、3D 图标、单车宝箱这类小物），不当项目成果，不进案例正文的证据图。原图放 `sources/work/gen/`，网页版由 `tools/prepare_assets.py` 导到 `assets/work/gen/`；要抠底用 `tools/cut_gen_clay.py` 那种按边框颜色去底的办法。用了生成图的封面，来源标签必须换成「原始界面 + 生成插画」或「生成插画」，首页「精选作品」下面那句也写明封面插画是 AI 生成的。生成图不许画成像真界面的样子冒充原稿。
- 例外（2026-11-18 本人选「AI 头像版」，卡 20261118-026 意见）：青桔 03 节三个用户画像的头像用 Figma AI 生成（原稿用的是网上找的照片），画像文字照 2021 原稿。本人意见「不用写ai生成……直接放置就好」：这张图来源标签照常用「研究材料」，图里和图注都不写 AI 生成。只限画像头像，不生成界面。
